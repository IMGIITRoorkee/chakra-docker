Preferred Method: Jenkins

Jenkins on lupin has one job per repository: canvas-chakra-backend, canvas-chakra-frontend, canvas-chakra-core and canvas-chakra-library. A push to master (library: staging) triggers the job, which connects to the server over SSH, runs git pull --rebase in the checkout and restarts the container or rebuilds the transpiler. A merged PR is live within about a minute.

  • Do not race Jenkins with a manual deploy. Wait for it, then verify with the smoke test.
  • The library job has missed recent merges; after a library merge, check that cmsredesign serves the new commit.
  • The core checkout marks components.json as skip-worktree, so its production LibraryConfig does not block the pull.

Fallback: Git Bundle

The server has no GitHub credentials for the private repositories, so a manual deploy ships the commits as a git bundle and fast-forwards. Access paths are in the private chakra-ops skill.

# Locally git fetch origin git bundle create repo.bundle origin/master ^<server HEAD> # Copy repo.bundle to the server, then in the checkout: git fetch /tmp/repo.bundle refs/remotes/origin/master:refs/remotes/origin/master git merge --ff-only origin/master

Never git clean -x or git reset --hard a server checkout: ignored and skip-worktree files such as .env and components.json hold production settings.

Transpiler Restart

The transpiler runs as a Flask process in tmux, outside Docker. After pulling chakra-core, rebuild the Scala binary and restart the session:

# In ~/chakra-docker/codebase/chakra-core PATH=$HOME/.local/share/coursier/bin:$PATH bash pack.sh # Restart Flask on 127.0.0.1:5000 tmux kill-session -t chakra-core tmux new-session -d -s chakra-core '~/chakra-core-start.sh; exec bash'

Always use chakra-core-start.sh

The transpiler token SECRET_FLASK contains $. Sourcing the core .env in a shell mangles it, and every preview then fails with "Invalid token". The start script reads .env literally. The production LibraryConfig (assets_host, chakra_base_url) lives in the locked components.json and must name chakra.channeli.in:

"assets_host": "https://chakra.channeli.in/media/preview" "dummy_assets_host": "./assets"

Full Stack Restart

Brings up all Docker containers. Use this after a server reboot or a compose change.

# In ~/chakra-docker CURRENT_UID="$(id -u):$(id -g)" docker-compose up -d

The CURRENT_UID variable ensures containers run with the correct user permissions for bind-mounted volumes. This starts all five containers:

ContainerService
chakra-docker_chakra-backend_1Django (Gunicorn + Daphne + Celery)
chakra-docker_chakra_frontend_1Next.js (PM2)

Note: The transpiler runs outside Docker in a tmux session and must be restarted separately. lsyncd and nginx are host services managed by systemd.

Restarting Backend Processes

The production supervisord.conf has no supervisorctl section, so individual programs cannot be restarted from inside the container. Restart the whole container instead; Celery restarts on its own if it exits (autorestart=true).

docker restart chakra-docker_chakra-backend_1 # check the processes docker top chakra-docker_chakra-backend_1
