How Chakra Works

Chakra is a Component Content Management System (CCMS). Instead of writing HTML, editors compose pages from pre-built UI components (sliders, cards, tables, etc.) in a visual editor. The system stores these as XML, then converts them to static HTML for delivery.

The Pipeline

  1. Edit — Editor uses Next.js frontend to compose page from components
  2. Save — Component tree saved as XML in website/XML/
  3. Preview — Transpiler converts XML → HTML in-memory, returns to browser
  4. Publish — Transpiler writes HTML to website/HTML/
  5. Sync — lsyncd pushes HTML to root2 via rsync
  6. Serve — Nginx on root2 serves static HTML to public users

Two-Server Architecture

Production runs on two physical servers on the same network (192.168.121.x). They are connected by lsyncd — a daemon on root1 that watches directories and rsyncs changes to root2 in near-real-time over SSH.

root1 / bifrost (192.168.121.230)

Application server. Runs all logic, stores all source data.

  • Docker containers: Django backend, Next.js frontend, PostgreSQL, Memcached, RabbitMQ
  • Host processes: Flask + chakra-core (tmux), lsyncd, Nginx
  • Filesystem: website/ (XML + HTML + JoshUsers), media_files/, reverse proxy configs
  • S3 mounts: s3bucket, s3bucket2 (backups)
  • Cron: Weekly DB backup, daily incremental to S3, hourly preview cleanup

root2 / edith (192.168.121.188)

Static file server. Serves published websites to the public. No app logic.

  • Nginx: 18+ subdomain server blocks (cec.iitr.ac.in, ece.iitr.ac.in, etc.)
  • inotifywait: Watches /etc/nginx/ for config changes → auto-reloads nginx
  • Filesystem: /home/root2/new_website/ (70 GB, synced from root1)
  • S3 mount: faculty.iitr.ac.in served from s3bucket/public/Websites/ - the same bucket also holds DB dumps and Omniport backups
  • No Docker, no database, no cron, no application code

lsyncd Sync Streams

Configured at /etc/lsyncd/lsyncd.conf.lua on root1. All streams use SSH key auth (/home/root1/.ssh/website-key).

faculty.iitr.ac.in is served directly from the S3 mount at /home/root2/s3bucket/public/Websites/, bypassing the CMS pipeline entirely. That bucket also stores database dumps and Omniport backups - see Backups & S3.

The Transpiler (chakra-core)

A Scala binary wrapped in a Flask API. Converts XML component trees to static HTML using rules from components.json.

How It Runs

  • Location: /home/root1/chakra-docker/codebase/chakra-core/
  • Process: flask run --host=0.0.0.0 --port=5000 in tmux
  • Binary: ./chakra-core (built via sbt assembly / pack.sh)
  • Config: components.json (320+ component definitions)

Django POSTs to http://127.0.0.1:5000/. Flask decodes params, runs the Scala binary as a subprocess, returns stdout (preview) or writes to disk (publish).

Process Management

Inside the Django Docker container, supervisord manages three processes:

HTTP

Gunicorn

5 workers, gthread, 120s timeout. Handles all Django REST API traffic on port 8000.

WS

Daphne

ASGI server for WebSocket connections on port 8001. Real-time features.

BG

Celery

Background task worker. Consumes from RabbitMQ. Runs cron jobs (preview cleanup, notice publishing).
