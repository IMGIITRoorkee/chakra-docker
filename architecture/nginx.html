Nginx & Routing

Two separate nginx instances — application proxy on root1, static file server on root2

Two Nginx Instances

Chakra uses two separate nginx instances on two different servers. Root1 (bifrost) proxies application traffic for the CMS editor and APIs. Root2 (edith) serves published department websites as static files.

root2
subdomain.iitr.ac.in

Root1 Nginx — chakra.channeli.in

Application traffic for editors and the CMS API. Template: nginx/conf.d/chakra_stencil.conf. Listens on 443 SSL with rate limiting at 16r/s per IP (chakra_zone).

Upstream Definitions

All upstreams bind to 127.0.0.1 since Docker containers use network_mode: host.

# upstreams.conf upstream gunicorn { server 127.0.0.1:8000; } upstream daphne { server 127.0.0.1:8001; } upstream next { server 127.0.0.1:3000; }

Root2 Nginx — Subdomain Sites

Each department subdomain gets its own nginx server block, generated by ConfMan and synced via lsyncd. All listen on 443 SSL with certificates at /certificates/iitr-certificate/.

Per-Subdomain Server Block

# Example: cec.iitr.ac.in server { listen 443 ssl; server_name .cec.iitr.ac.in; root '/home/root2/new_website/cec'; ssl_certificate /certificates/iitr-certificate/...; ssl_certificate_key /certificates/iitr-certificate/...; include conf.d/includes/compression.conf; }

Faculty Profile Aliases

Faculty profile pages use location blocks with alias directives to map friendly URLs to specific HTML files:

# Faculty profile alias location "/~ECE/Faculty_Name" { alias '/home/root2/new_website/Departments/ .../Faculty/100XXX.html'; }

Faculty Personal Websites

Faculty personal websites are served from S3-mounted storage:

root /home/root2/s3bucket/public/Websites/$dep/$fac;

Cross-Server Proxy Rules

Some subdomain routes on root2 need dynamic content from root1. These use proxy_pass rules pointing back to root1’s internal IP.

# Dynamic pages served from root1 proxy_pass http://192.168.121.230;

The conf.d/includes/ directory on root2 contains faculty routes and short URL configs, all synced from root1 via lsyncd.

Rate Limiting

Root1 nginx enforces rate limiting to protect backend services from excessive requests.

# Rate limit zone definition limit_req_zone $binary_remote_addr zone=chakra_zone:10m rate=16r/s;

Limits to 16 requests per second per IP address. This applies to all proxied routes (backend API, frontend, WebSocket upgrade requests).
