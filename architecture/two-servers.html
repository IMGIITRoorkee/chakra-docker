Two-Server Setup

root1 (bifrost) + root2 (edith) — connected by lsyncd over SSH

Why Two Servers?

Chakra separates application logic from public-facing delivery. root1 handles all CMS operations (editing, preview, publish, database). root2 is a hardened static file server that only serves pre-built HTML to the public internet.

  • root2 has no application code, no database, no Docker — minimal attack surface
  • root1 can be restarted/updated without affecting live websites (lsyncd catches up)
  • Different security policies per server — root2 only needs ports 80/443 open

The Connection: lsyncd

Config: /etc/lsyncd/lsyncd.conf.lua on root1. SSH key: /home/root1/.ssh/website-key.

#Source (root1)Target (root2)Content
1website/HTML//home/root2/new_website/Published pages + assets/
2website/JoshUsers/new_website/Josh Users/Josh user websites
3reverse_proxy.../subdomains//etc/nginx/sites-available/subdomains/Subdomain configs
4reverse_proxy.../shorturls//etc/nginx/conf.d/includes/Short URL routes
5reverse_proxy.../josh-subdomains//etc/nginx/sites-available/josh-subdomains/Josh subdomain configs

What Does NOT Sync

  • website/XML/ — source content stays on root1 only
  • media_files/ — preview images served from root1 via chakra.channeli.in
  • Database, Docker volumes, application code

Auto-Reload Flow

When ConfMan generates a new nginx config on root1:

  1. Config written to reverse_proxy_configurations/subdomains/
  2. lsyncd detects change → rsyncs to root2 /etc/nginx/sites-available/
  3. inotifywait on root2 detects new file → runs hot-nginx-reload.sh
  4. Nginx reloads with zero downtime

Proxy Pass Exceptions

A few faculty profile routes on root2 proxy back to root1 for dynamic rendering:

# faculty-website-route.conf on root2 location "/~PH/Faculty_Name" { proxy_pass http://192.168.121.230/departments/PH/pages/...; }
