Frontend (Next.js)

Next.js editor UI on the AWS app server - visual page composition from UI-kit components

Container Overview

The frontend runs in the chakra-docker_chakra_frontend_1 container (image chakra-frontend:latest, Next.js 12, network_mode: host). It serves the editor on port 3000 behind the host nginx at chakra.channeli.in. The checkout is ~/chakra-docker/codebase/chakra-frontend; Jenkins pulls it and restarts the container when master changes.

Startup Command

bash /start.sh

next/start.sh runs yarn build only when a file in the checkout is newer than the last build or PROXY changed (it is baked into the build), then starts yarn start under PM2. A restart without a git pull is back up in about a second instead of rebuilding.

Runtime

  • Port: 3000
  • Process manager: PM2
  • Node: the container runs 17.4; CI pins 17.9 through .nvmrc
  • Proxy: host nginx forwards / and /api/ to :3000
  • PROXY env var: 127.0.0.1:8000 (set in the server's docker-compose.override.yml)
  • OAuth: NEXT_PUBLIC_* values in the locked .env.local point login at channeli.in with the chakra.channeli.in redirect

Dev Server

./scripts/run-dev.sh -d 60000 -p 61000

Runs Next.js dev mode inside Docker on high ports for local development.

What It Does

The frontend is a visual editor for composing pages from pre-built UI-kit components. Editors arrange components, and the frontend sends the component tree to the backend, which stores it as XML.

PagePurpose
DashboardFolder tree of the site; the first level of the editor's section opens by default
EditorVisual component composer: add, arrange and configure UI-kit components
PreviewRendered draft at laptop, tablet (768x1024) and phone (390x844) sizes
ManagePage maintainers, short URLs, edit log, file uploads
PermissionsManage user access and roles

Backend Integration

The frontend calls the backend with axios on relative /api/... URLs. Key integration points:

Image Picker

GET /api/generator/image?xml_page_pk={id}

Lists available images for a given page. The editor displays these in a picker UI so editors can insert images into their component trees.

Preview

GET /api/generator/preview?xml_page_pk={id}

Django renders the draft through the transpiler and returns HTML. Its images point at https://chakra.channeli.in/media/preview/... (the transpiler's assets_host; see Image Lifecycle).

API Client

Most requests go through one axios instance in src/utils/apiClient.js. It sends cookies and adds the CSRF header from the chakra_csrftoken cookie.

// src/utils/apiClient.js (trimmed) export const apiClient = axios.create({ withCredentials: true, headers: { 'Content-Type': 'application/json' }, }); // request interceptor: X-CSRFToken from the chakra_csrftoken cookie

URLs come from urls.js and start with /api. next.config.js rewrites /api/:path*/ to http://${PROXY}/:path*/, so in production the Next.js server forwards API calls to Gunicorn on 127.0.0.1:8000.

Component Workflow

The editor works on a JSON component tree. The backend converts it to XML on save, and the transpiler turns the XML into HTML.

1

Compose

Editor arranges UI-kit components in the visual editor interface.

2

Save

The tree is sent as JSON; the backend writes it to <page>.xml.draft under website/XML/.

3

Publish

The draft becomes the published XML and is rendered to website/HTML/, which lsyncd copies to root2.
