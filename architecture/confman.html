ConfMan

Dynamic nginx configuration generator - approved subdomains and short URLs become root2 nginx config without hand edits

What ConfMan Does

ConfMan is a Django app in the backend on the AWS app server. When an admin approves a subdomain or a faculty short URL, ConfMan writes the nginx config file. lsyncd copies it to root2 and a watcher there reloads nginx, so no one edits nginx on root2 by hand.

1

Request

An editor or admin submits a subdomain or short URL request in the Chakra editor.

2

Approve

An admin approves it. A Django post_save signal fires.

3

Generate

The signal (or a Celery task, for short URLs) renders a template and writes the config. lsyncd syncs it to root2.

Data Models

ConfMan manages two models, both with an approval status (pending, approved, declined). Requests, approvals and rejections send no-reply emails.

Subdomain

Maps a folder to a subdomain (for example the ECE department folder to ece.iitr.ac.in). Stores the folder, short name, previous short name (for renames), home page and approval status.

Shorturl

Attached to a page through a generic relation. Faculty short URLs (/~EE/<name>) become nginx location blocks that alias the page's published HTML file. A declined request can carry a rejection reason. Folder short URLs are stored too, but only faculty short URLs generate nginx config.

Signal Flow

Subdomains

# confman/signals/subdomain.py # 1. Skip unless approved and the folder has a parent # 2. Josh folder? use josh-subdomain_template.txt, # else subdomain_template.txt # 3. Substitute short name, root path, certificates # 4. Write subdomains/{shortname}.conf # or josh-subdomains/{shortname}.conf # 5. On rename, move shorturls/{old}.conf to {new}.conf

Short URLs

# confman/signals/short_url.py # 1. Approved faculty short URL: # queue a Celery task # 2. For each approved subdomain, # rewrite shorturls/{shortname}.conf # from its published pages # 3. iitr.ac.in: shorturls/iitr.conf

Short URLs are regenerated as a whole file per subdomain, from the database. Pages that were never published are skipped. A third signal, josh_folder_update.py, rewrites shorturls/josh-route.conf whenever a folder under JoshUsers changes.

Known gap: confman/config_makers/ ships the Josh, Josh-URL and short-URL templates, but not subdomain_template.txt. Until it is restored, approving a new department or centre subdomain logs "Unable to read subdomain template" and writes nothing. Existing subdomain configs are unaffected.

Config Directories

ConfMan writes under CONFIG_DIR (/reverse_proxy_configurations/ in the backend container). Each directory is its own lsyncd stream with delete = true, so root2 holds an exact mirror.

DirectoryOn root2Contents
subdomains//etc/nginx/sites-available/subdomains/Department and centre server blocks (38)
josh-subdomains//etc/nginx/sites-available/josh-subdomains/Josh site server blocks
shorturls//etc/nginx/conf.d/includes/One short-URL file per subdomain, iitr.conf, josh-route.conf, and the hand-maintained includes that live alongside them (main-route.conf, faculty-website-route.conf, ...)

Because shorturls/ mirrors the whole conf.d/includes/ directory, any include changed on root2 must also be changed in the AWS copy, or the next sync reverts it.

Josh User Subdomains

Josh sites are static uploads under JoshUsers/ (for example gate, jam, drc). ConfMan treats a subdomain on a Josh folder the same way, but uses josh-subdomain_template.txt and writes to josh-subdomains/. Their files reach root2 through the separate JoshUsers/ lsyncd stream.

End-to-End Flow

From approval to live subdomain, the entire pipeline is automated:

On the AWS app server

  1. Admin approves the request in the editor
  2. Signal or Celery task renders the template
  3. Config written under reverse_proxy_configurations/
  4. lsyncd pushes it to root2 through the reverse tunnel

On root2

  1. Config arrives in sites-available/ or conf.d/includes/
  2. The hot-nginx-reload service sees the change (inotifywait on /etc/nginx/)
  3. It runs nginx -t; on success, service nginx reload
  4. On failure it logs the path and keeps the old config running

Short URLs depend on Celery. If the worker is down, approvals are saved but no config is written; the CeleryUp health metric and scripts/smoke.sh catch that.
