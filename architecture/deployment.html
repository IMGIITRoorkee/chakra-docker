Preferred Method: Jenkins

Each repository has a dedicated Jenkins job that handles pulling, building, and restarting services. Use Jenkins whenever possible — manual deployment is a fallback for when Jenkins is unavailable or a quick hotfix is needed.

Manual Fallback — Backend

Pull latest code and restart the Docker container. The backend code is bind-mounted read-only, so a container restart picks up the new code.

# SSH into root1, then: cd /home/root1/chakra-docker/codebase/chakra-backend git pull origin master --rebase docker restart chakra-docker_chakra-backend_1
StepWhat Happens
git pull --rebaseFetches and rebases local commits on top of remote master
docker restartsupervisord restarts Gunicorn, Daphne, and Celery inside the container

Manual Fallback — Transpiler

The transpiler runs as a Flask process in tmux, outside Docker. Deployment requires rebuilding the Scala binary and restarting Flask.

# SSH into root1, then: cd /home/root1/chakra-docker/codebase/chakra-core source chakra-core-env/bin/activate git fetch origin && git reset --hard FETCH_HEAD ./pack.sh # Then in the tmux session: # Ctrl+C to stop Flask, then restart: flask run --host=0.0.0.0 --port=5000

Warning: git reset --hard

git reset --hard FETCH_HEAD wipes local changes to components.json. This file contains the assets_host configuration that differs between local and production. After reset, verify that assets_host is set correctly:

"assets_host": "https://chakra.channeli.in/media/preview" "dummy_assets_host": "./assets"

Manual Fallback — Frontend

The Next.js frontend runs in its own Docker container with PM2.

# SSH into root1, then: cd /home/root1/chakra-docker/codebase/chakra-frontend git pull origin master --rebase docker restart chakra-docker_chakra_frontend_1

Full Stack Restart

Brings up all Docker containers. Use this after server reboot or major configuration changes.

# SSH into root1, then: cd /home/root1/chakra-docker CURRENT_UID="$(id -u):$(id -g)" docker compose up -d

The CURRENT_UID variable ensures containers run with the correct user permissions for bind-mounted volumes. This starts all six containers: backend, frontend, database, cache, message-broker, and libretranslate.

Note: The transpiler (Flask + chakra-core) runs outside Docker in a tmux session and must be restarted separately.

Supervisor Control

Inside the backend container, use supervisord to inspect individual processes:

# Enter the backend container docker exec -it chakra-docker_chakra-backend_1 bash # Check process status supervisorctl status # Restart a specific process supervisorctl restart gunicorn supervisorctl restart daphne supervisorctl restart celery
