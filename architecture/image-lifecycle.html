Upload

An editor uploads an image in the editor. The backend converts PNG and JPEG to WebP, prefixes the name with a hash of the page's primary key, and writes it to the XML folder's assets/ directory on the AWS app server.

Request

# Endpoint POST /api/generator/image/ # PNG/JPEG: converted to WebP (max 1920px wide, quality 82) # unless animated or conversion fails filename = sha256( str(xml_page_pk).encode('utf-8') ).hexdigest() + "_" + stored_name

Result

AspectDetail
Written towebsite/XML/{node}/assets/{filename}
Response{ value: "./assets/{filename}", key: original_name }
SyncFile lives ONLY on the AWS app server. Not synced to root2.

Key point: lsyncd syncs website/HTML/ and website/JoshUsers/, never website/XML/. Uploads stay on the app server until the page is published. Backups of XML/ go to S3 (see Backups).

Preview

When an editor previews a page, Django calls the transpiler with write_stdout=True. The transpiler rewrites image paths to absolute URLs so the browser can fetch them from chakra.channeli.in.

Flow

  1. Request: GET /api/generator/preview?xml_page_pk=123
  2. Django → Flask: calls the transpiler on 127.0.0.1:5000, sending the draft XML (or the published XML if there is no draft)
  3. Transpiler: ImageSpec.scala replaces "./assets" with assets_host from components.json: https://chakra.channeli.in/media/preview
  4. Django: copies the page's images from website/XML/{node}/assets/ to media_files/preview/
  5. Browser: loads them from /media/preview/, served by the host nginx

If preview images are missing: check the image host in the browser's network tab. A 410 means assets_host still names canvas.channeli.in; a 404 means the file was not copied into media_files/preview/.

Preview images are temporary copies. They are served only by the app server and never reach root2.

Publish

Publishing converts XML to HTML on disk and copies the page's images next to the HTML. After lsyncd syncs, each image exists in three places.

Publish Steps

  1. XMLPage.publish() in generator/models/page.py
  2. Calls the transpiler with write_stdout=False → writes HTML to website/HTML/{node}/
  3. The HTML keeps relative "./assets" paths
  4. Deletes this page's old images (same hash prefix) from website/HTML/{node}/assets/, then copies the current ones from website/XML/{node}/assets/
  5. lsyncd pushes HTML and assets to root2 through the reverse tunnel (delete = true, so removed images disappear from root2 too)

Serving

Public users never reach the app server. Their browser loads static HTML from root2, and images resolve through relative paths.

Request Flow

  1. User visits ece.iitr.ac.in/People/Faculty.html
  2. root2 nginx serves from the subdomain's root under /home/root2/new_website/
  3. HTML contains relative ./assets paths
  4. Browser resolves them to the same directory on root2
  5. For PNG and JPEG, nginx serves a .webp sidecar when the browser accepts WebP and one exists

Why Relative Paths Work

The published HTML file and its assets/ folder are siblings in the same directory. When the browser encounters ./assets/photo.webp in the HTML, it resolves relative to the page URL, which maps to the same directory on root2's filesystem.

# Directory structure on root2 /home/root2/new_website/Departments/<dept>/ index.html # <img src="./assets/abc123_photo.webp"> assets/ abc123_photo.webp # served by nginx

Older PNG/JPEG uploads get WebP sidecars from manage.py generate_webp_sidecars (photo.png.webp next to photo.png).

Listing (Frontend Image Picker)

The editor's image picker fetches a list of images already uploaded to the current page's XML node.

Request

# Endpoint GET /api/generator/image?xml_page_pk=123

Django scans the XML node's assets/ directory and filters files by the SHA-256 prefix derived from the page PK. Only images belonging to this page are returned.

Response

Returns a list for the image picker dropdown, allowing editors to re-use previously uploaded images without re-uploading.

Why prefix filtering matters: Multiple pages within the same XML node share the assets/ directory. The SHA-256 prefix ensures each page only sees its own uploads.

Deletion

Deleting an image removes it from the XML source only. Published copies stay until the page is published again.

Request

# Endpoint DELETE /api/generator/image?xml_page_pk=123 &image_name=photo.webp
