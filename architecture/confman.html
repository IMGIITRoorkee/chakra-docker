ConfMan

Dynamic nginx reverse proxy configuration generator — zero manual nginx editing

What ConfMan Does

ConfMan is a Django app that generates nginx reverse proxy configurations dynamically. When an admin approves a subdomain or short URL, ConfMan writes the nginx config file automatically. Combined with lsyncd and inotifywait, this means zero manual nginx configuration is needed.

1

Request

User submits a subdomain or short URL request through the admin interface.

2

Approve

Admin approves the request. Django signal fires in confman/signals/subdomain.py.

3

Generate

Signal reads template, substitutes variables, writes config to disk. lsyncd syncs to root2.

Data Models

ConfMan manages two primary models, both with an approval workflow.

Subdomain

Maps folder paths to subdomains (e.g., cec → cec.iitr.ac.in). Includes fields for the folder path, short name, certificate paths, home page, and approval status.

Shorturl

Maps short URLs to destinations (e.g., /convocation → target page). Also requires admin approval before the config is generated.

Signal Flow

When an admin approves a subdomain, a Django signal triggers the config generation pipeline.

# confman/signals/subdomain.py # 1. Read template from confman/config_makers/ # 2. Substitute variables: # - short_name, path, certificate paths, home_page # 3. Write config to: # reverse_proxy_configurations/subdomains/{shortname}.conf # 4. lsyncd picks up change → syncs to root2 # 5. inotifywait on root2 → nginx -s reload

Config Directories

Generated configs are organized into directories on root1, then synced to root2 by lsyncd.

VariablePathContents
CONFIG_DIR/reverse_proxy_configurations/Base directory for all generated configs
SUBDOMAIN_DIR.../subdomains/Per-subdomain nginx server block configs
JOSH_SUBDOMAIN_DIR.../josh-subdomains/Josh user subdomain configs
SHORT_URL_DIR.../shorturls/Short URL location block configs

Josh User Subdomains

In addition to department subdomains, ConfMan also handles Josh user subdomain configs. These follow the same approval and generation workflow but are written to a separate directory (josh-subdomains/) and synced to a different location on root2.

End-to-End Flow

From approval to live subdomain, the entire pipeline is automated:

On root1

  1. Admin approves subdomain in Django admin
  2. Django signal generates nginx config from template
  3. Config written to reverse_proxy_configurations/subdomains/
  4. lsyncd detects change, rsyncs to root2

On root2

  1. Config arrives at /etc/nginx/sites-available/subdomains/
  2. inotifywait detects new file in /etc/nginx/
  3. Runs hot-nginx-reload.sh
  4. Executes nginx -s reload — subdomain is live
