Transpiler (chakra-core)

Scala binary wrapped in a Flask API — converts XML component trees to static HTML

How It Runs

The transpiler is a Scala binary wrapped in a lightweight Flask API. It runs on the host (not in Docker) inside a persistent tmux session.

Runtime Details

  • Location: /home/root1/chakra-docker/codebase/chakra-core/
  • Process: flask run --host=0.0.0.0 --port=5000 in tmux session
  • Binary: ./chakra-core (built via sbt assembly / pack.sh)
  • Config: components.json (320+ component definitions)

Django Integration

Django POSTs to http://127.0.0.1:5000/ with the following parameters. Flask decodes them, constructs a CLI command, and runs the Scala binary as a subprocess.

ParameterPurpose
input_pathPath to the XML source file
output_pathPath for the generated HTML output
write_stdoutIf true, return HTML as string instead of writing to disk
transpiler_components_pathPath to components.json
menuMenu JSON for navigation generation
headerHeader HTML/config
footerFooter HTML/config
secret_tokenAuthentication token (must match SECRET_FLASK)

Constructed CLI Command

./chakra-core --write-stdout -i {input_path} -c {components.json} -m {menu}

The CODEBASE_PATH env var prefixes all file paths so the transpiler can locate XML files on disk.

components.json

The component definition file contains 320+ UI components, each specifying CSS classes, JS files, and allowed child components. This is the source of truth for what the transpiler can render.

Asset Configuration

"assets_host": "https://chakra.channeli.in/media/preview" "dummy_assets_host": "./assets"

The replaceAssets logic in ImageSpec.scala controls how image paths are resolved. When writeToStdout=true, the transpiler replaces "./assets" with the full assets_host URL in Image and FluidImage src attributes.

Preview vs Publish

The transpiler operates in two distinct modes depending on how it is invoked by Django.

Preview Mode

  • Flag: --write-stdout
  • replaceAssets: true
  • Image paths: Absolute URLs (https://chakra.channeli.in/media/preview)
  • Output: HTML string returned to Django, sent to browser

Publish Mode

  • Flag: -o {output_path}
  • replaceAssets: false
  • Image paths: Relative ./assets
  • Output: HTML file written to disk at output path

Building the Transpiler

The Scala binary is compiled using sbt (Scala Build Tool) and packaged into a standalone executable.

# Build the fat JAR sbt assembly # Or use the packaging script ./pack.sh

After building, the ./chakra-core binary is ready to be invoked by the Flask wrapper. The Flask server must be restarted if the binary is updated.
