Two-Server Setup

AWS app server + root2 (edith) - connected by lsyncd over a reverse SSH tunnel, as of 15 November 2026

Why Two Servers?

Chakra separates application logic from public-facing delivery. The AWS app server handles all CMS operations (editing, preview, publish, database). root2 is a static file server on the IITR network that only serves pre-built HTML to the public.

  • root2 runs no Chakra code and no database - minimal attack surface
  • The app server can be restarted or updated without affecting live websites (lsyncd catches up)
  • The editor is reachable only from the IITR network; the public sites are open to everyone

History: until 12 November 2026 the app server was root1 (bifrost) on campus. It failed, and the AWS instance took over with the same containers and repositories.

The Connection: lsyncd

Config: /etc/lsyncd/lsyncd.conf.lua on the AWS server. AWS cannot open connections into the campus network, so root2 opens a reverse SSH tunnel to AWS and lsyncd's rsync runs through it. Every stream uses delete = true. Details on lsyncd & Sync.

#Source (AWS)Target (root2)Content
1website/HTML//home/root2/new_website/Published pages + assets/
2website/JoshUsers/new_website/Josh Users/Josh user websites
3reverse_proxy.../subdomains//etc/nginx/sites-available/subdomains/Subdomain configs
4reverse_proxy.../shorturls//etc/nginx/conf.d/includes/Short URL routes and the main-site includes
5reverse_proxy.../josh-subdomains//etc/nginx/sites-available/josh-subdomains/Josh subdomain configs

What Does NOT Sync

  • website/XML/ - source content stays on the AWS server only
  • media_files/ - preview images are served by the AWS server via chakra.channeli.in
  • Database, Docker volumes, application code

Auto-Reload Flow

When ConfMan generates a new nginx config on the AWS server:

  1. Config written to reverse_proxy_configurations/subdomains/ (or shorturls/)
  2. lsyncd detects the change → rsyncs it to root2 through the tunnel
  3. hot-nginx-reload on root2 sees the file change → runs nginx -t
  4. Nginx reloads with zero downtime if the test passes

Proxy Pass Exceptions

A few faculty profile routes in faculty-website-route.conf on root2 proxy to an older campus web host instead of serving a file:

# faculty-website-route.conf on root2 location "/~PH/Faculty_Name" { proxy_pass http://<legacy host>/departments/PH/pages/...; }
