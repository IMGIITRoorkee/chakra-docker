lsyncd & Sync

Live Syncing Daemon - continuous rsync from the AWS app server to root2 through a reverse SSH tunnel, as of 15 November 2026

What is lsyncd?

lsyncd (Live Syncing Daemon) watches directories on the AWS app server for file changes and triggers rsync to push them to root2 within seconds. It is the backbone of the two-server architecture: published content and nginx configs reach the static file server automatically.

Configuration

  • Config file: /etc/lsyncd/lsyncd.conf.lua on the AWS server (drift-checked by the env guard)
  • Service: systemd unit lsyncd-chakra, running as the app user
  • Mode: default.rsync, delay = 3 seconds, delete = true on every stream
  • Transport: SSH through the reverse tunnel, with its own /etc/lsyncd/ssh_config (batch mode, pinned known hosts)

Logging

  • Log file: /var/log/lsyncd/lsyncd.log
  • Status file: /var/log/lsyncd/lsyncd.status
  • Health metrics: LsyncdUp and Root2TunnelUp in CloudWatch, every 5 minutes

The Reverse Tunnel

The AWS server cannot open connections into the IITR network, so the connection runs the other way. root2 starts an SSH session to the AWS server and forwards a port on the AWS loopback interface back to its own SSH port. lsyncd then connects to that loopback port as if root2 were local.

# root2: aws-tunnel.sh, from cron at boot and every 5 minutes (flock keeps one copy) ssh -N -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 \ -R 127.0.0.1:2222:127.0.0.1:22 <aws server> # reconnects 10 seconds after any drop, logging to aws-tunnel.log # AWS: /etc/lsyncd/ssh_config Host root2 HostName 127.0.0.1 Port 2222

If the tunnel is down, lsyncd keeps retrying (insist = true) and catches up once root2 reconnects. Users, keys and hostnames are in the private chakra-ops skill.

5 Sync Streams

lsyncd maintains 5 independent sync streams, each watching a directory under codebase/chakra-backend/ on the AWS server and pushing changes to a corresponding directory on root2.

#Source (AWS)Target (root2)What Syncs
1website/HTML//home/root2/new_website/Published pages + assets/ folders (excludes /Josh Users/)
2website/JoshUsers//home/root2/new_website/Josh Users/Josh user websites
3reverse_proxy_configurations/subdomains//etc/nginx/sites-available/subdomains/Subdomain nginx server block configs
4reverse_proxy_configurations/shorturls//etc/nginx/conf.d/includes/Short URL location blocks and the hand-written includes such as main-route.conf
5reverse_proxy_configurations/josh-subdomains//etc/nginx/sites-available/josh-subdomains/Josh subdomain configs

delete = true

Each target is a mirror of its source. A file removed on AWS is removed on root2, and a file that exists only on root2 inside a synced tree is deleted at the next sync. To add or change anything in these trees (a favicon, a nginx include), do it on the AWS side; edits made directly on root2 are lost.

What Does NOT Sync

Not everything on the AWS server is pushed to root2. Several directories and resources stay on AWS only.

ResourceLocationWhy Not Synced
website/XML/AWS onlySource XML is only needed for editing and transpilation, not serving
media_files/AWS onlyPreview images are served by the AWS server via chakra.channeli.in/media
PostgreSQL databaseAWS Docker volumeApplication database only needed by Django
Docker volumesAWS onlyNo Chakra containers run on root2

Key insight: Only published HTML reaches root2. Preview images are served from the AWS server directly via chakra.channeli.in.

Auto-Reload on root2 (inotifywait)

When lsyncd pushes new nginx configs to root2, they need to take effect without manual intervention. The hot-nginx-reload systemd service on root2 handles this.

# root2: hot-nginx-reload.sh, run by the hot-nginx-reload service inotifywait -q -m -r -e modify -e create -e close_write -e moved_to /etc/nginx/ → wait for the burst of changes to settle → nginx -t → service nginx reload # only if the test passed

A config that fails nginx -t is not loaded; nginx keeps serving the previous configuration and the failure is logged.

Configuration

The live lsyncd.conf.lua defines one helper and calls it once per stream:

-- /etc/lsyncd/lsyncd.conf.lua (AWS) local B = "<home>/chakra-docker/codebase/chakra-backend" local RSYNC = { rsh = "/usr/bin/ssh -F /etc/lsyncd/ssh_config", links = true, times = true, perms = true, protect_args = true, } settings { logfile = "/var/log/lsyncd/lsyncd.log", statusFile = "/var/log/lsyncd/lsyncd.status", insist = true, } local function stream(src, dst, extra) sync { default.rsync, source = B .. src, target = "root2:" .. dst, delete = true, delay = 3, rsync = RSYNC } -- plus extra end stream("/website/HTML/", "/home/root2/new_website/", { exclude = { "/Josh Users/" } }) stream("/website/JoshUsers/", "/home/root2/new_website/Josh Users/") -- ... and the three reverse_proxy_configurations streams
